# CLAUDE.md: Auto Reply Web (web UI for the Auto Reply Leafyrino plugin)

## Project
Optional, separate project: a static website (hosted on Vercel, everything runs in the user's browser) that edits the `data/config.json` of the Auto Reply plugin (sibling repo `../auto-reply-plugin/`, Lua plugin for Leafyrino, a Chatterino fork). The plugin must keep working without this app. Owner: Pavlo. Chat language with the owner: English; UI text is Russian.

**Start here:** `PLAN.md` (decisions, architecture, edge cases, phases), `docs/CONTRACT.md` (the plugin's config contract), `docs/adr/0001-stack.md` (stack, accepted). Status: Phases 0-2, 2b, 2c, 3 and 4 done on the dev Mac (3: Rules page and constructor, `docs/phase-3-plan.md`; 4: Timers and Redeems, `docs/phase-4-plan.md`) (2b: the browser file layer, `docs/phase-2b-plan.md`; 2c: open + download as the main flow because Chrome blocks the plugin folder, `docs/phase-2c-plan.md`); the hosted-site direction is in `PLAN.md` section 0a. Pending: the owner's manual check of real folders (`docs/manual-checks/file-access.md`), then Phase 5 (main page, layout decided with the owner), after the edge-case questions.

## Plugin folder link and install/update (plugin 0.6.1)
The plugin folder can be a link to a user folder (`scripts/link-config.*`, or the command the Plugin card shows); the site opens that folder with direct access, edits `data/config.json`, and installs/updates the plugin files (`src/ui/data/plugin-install.ts`, bundle from `vendor/plugin/` via `pnpm sync-plugin`: every top-level `*.lua` + `info.json`, never `tests/`). Backups of replaced code: `.backup/<version>/` inside the folder; link-script backups of the original folder: `<app data>/auto-reply-backups/` (never inside `Plugins`: Leafyrino loads every folder there). Plan and decisions: `docs/phase-plugin-link-plan.md`. A plugin release now means: bump version in the plugin repo, `pnpm sync-plugin`, redeploy. Windows junction scripts are UNVERIFIED.

## Twitch login (plugin 0.8.0+, live adoption 0.8.2+)
Settings has a "Twitch API" card (`TwitchCard.svelte`, state in `state/twitch.svelte.ts`, flow in `data/twitch-flow.ts`, file in `data/helix-file.ts`): device-code login from the page (id.twitch.tv allows cross-origin requests; verified with curl: `Authorization` is an allowed header on `/oauth2/validate`, `client-id` is not, so the site sends only `Authorization`), result written to `data/helix.json`, which also turns `helix_enabled` on as a normal unsaved edit. The site writes `helix.json` ONLY on login and logout; the plugin owns it otherwise and is the only one that refreshes tokens (Twitch rotates refresh tokens). Plugin < 0.8.2 reads `helix.json` only at start: the card says to restart it (`features.helixSync`). The Redeems "Add" button (and `#/redeems/new`) is blocked until logged in AND `helix_enabled` (`state/twitch-gate.ts`), only for plugin folders with plugin >= 0.8.0. The Client ID is `TWITCH_CLIENT_ID` in `src/shared/twitch.ts` (the owner's public Twitch app, not a secret; the plugin has the same value in `helix.CLIENT_ID` since 0.8.3, change both together; a `client_id` already in helix.json wins). UNVERIFIED against real Twitch from the browser (tests use a scripted `id.twitch.tv`), and `/oauth2/revoke` from a browser. The sidebar folder card has an Update button when the bundled plugin is newer (`data/plugin-update.ts`); `featuresFor(version, pluginBundle.version)` makes "newer than this app" mean newer than the bundle.

## Protected users, moderator check (plugin 0.9.0+, scope `user:read:moderated_channels`)
`ProtectedUsers.svelte` (used in Settings "Защита от мута" and in the redeem editor): two independent `<details>` dropdowns, Mods and VIP, each with a "Загрузить с Twitch" button, one `role=switch` per person (ON = protected = in `protect_users`; OFF = may be muted = in `unprotect_users`, which beats badges and bots in the plugin) and a "paste the answer of /mods or /vips" box. Pure model in `state/protect-model.ts`; fetch state in `state/protect-fetch.svelte.ts`; Helix client in `data/helix-api.ts` over an injected `fetch`, CSP `connect-src` allows `https://api.twitch.tv` (and id.twitch.tv) only. Twitch answers Get Moderators / Get VIPs ONLY for the channel owner's own token (VERIFIED in the reference: broadcaster_id must equal the token's user), so Fetch is enabled only when the logged-in account is the channel; for other channels the paste route is the way. The token is read for ONE call (`withHelixToken` in `data/helix-file.ts`, passed to a callback, never returned or stored); the site never refreshes it (an expired token says "start the plugin or log in again"). `state/mod-check.svelte.ts`: owner = channel equals the login (no request), otherwise Get Moderated Channels (needs the new scope; older logins get "log in again", `TwitchCard` shows the hint). In the redeem editor a NEW reward needs a passed check on its channel (owner or moderator; choosing another channel resets it), only for plugin folders with plugin >= 0.8.0; editing an existing reward is never blocked. Off switches need plugin 0.9.0 (`features.protectOverride`). UNVERIFIED against real Twitch from a browser: the live response shapes of Get Moderated Channels and Get Moderators (docs read only as summaries). Known flaky e2e test: `a11y.spec.ts` "keyboard alone" (focus in the dialog), fails rarely under load, not reproduced on demand.

## noword condition (plugin 0.10.0+)
Condition type `noword` (negative match, same word list format as `anyword`): shown in the condition editor as "Исключить слова" (`features.noword`, hidden for older plugin folders with a version note; an existing one still shows). The "at least one ordinary condition" rule is the plugin's own `rules.validate_set`, called from `src/lua/uichecks.lua` `condition_error` (shown under the conditions, blocks Save); preview/analysis run the real Lua. Vendored plugin is 0.10.0. UNVERIFIED in the real app (stub and WASM tests only).

Accordion of four ways to start (`src/ui/components/Accordion.svelte`, one open at a time; `src/ui/state/welcome.ts` holds the default/disabled/problem rules; strings in `ru.welcome.sections`): linked folder with direct access (open by default on Chrome/Edge), install plugin + link, open config.json (any browser, open by default without direct access), demo. ## App shell, notices, routes, preview modal
- Top bar (`TopBar.svelte`) with a bell icon and an anchored popover (`NoticePanel.svelte`): every non-success notice lives there; `state/notices.ts` (`collectNotices`, `newErrorIds`) is the single source for the list, the count, the red badge and the rule that a NEW error opens the popup once. `Banners.svelte` keeps only the success banner (reload command). Page-level banners (Timers old plugin, Redeems moderator note / protect warning) stay on their pages. Only real (trusted) clicks close the popup: the download helper clicks a hidden link.
- Routes live in the URL hash (`state/route.ts` pure, `state/route.svelte.ts` router): `#/rules`, `#/rules/new`, `#/rules/<id>`, same for `timers` and `redeems`, `#/settings`. Add and edit are full pages (`pages/*EditPage.svelte` around the existing editors; leaving an editor uses `replace`); unknown ids fall back to the list. Leaving an editor discards its draft (no guard yet); the list selection on Rules is lost when visiting an editor.
- "Проверка" is a modal (`PreviewDialog.svelte` around `RulePreview`): button before "Добавить" on Rules and Timers, and a button on the rule/timer editor pages that checks the draft. Its inputs live in `state/preview-state.svelte.ts` (reset in `session.leave`).
- Chips (`ChipList.svelte`, the only chip markup) have `margin: var(--s3) 0` in `.chips`.

## Commands
Toolchain: Node >= 22 and pnpm (pinned in `package.json`); `scripts/prepare.sh` installs a pinned pnpm into `.tools/` (gitignored) and runs every check.
- `pnpm dev`: Vite dev server (hot reload, opens the browser); there is no backend, so try the site with the demo mode or a real folder in Chrome/Edge. `pnpm preview`: builds, then serves the production build with the production headers. `pnpm build`: output `dist` (what Vercel deploys).
- `pnpm lint`, `pnpm typecheck`, `pnpm test` (node:test for scripts + Vitest), `pnpm sync-plugin:check` (`pnpm sync-plugin` re-vendors the plugin Lua; plugin repo read-only), `pnpm test:e2e` (builds `dist-e2e` with `--mode e2e`, then Playwright against `vite preview` and the dev server; the browser lives in `.tools/browsers`, installed by `scripts/prepare.sh`).
- `scripts/prepare.sh [--check] [--no-e2e]`: set up, then lint, typecheck, tests, vendor check, build, e2e.
- Project agents in `.claude/agents/` (architect, backend-dev, frontend-dev, qa-tester); commands `/adr`, `/spike`, `/contract-check`.
- Layout: `src/shared` (config model, merge, ids, demo sample, security headers; no I/O), `src/lua` (WASM Lua host + worker client), `src/ui/data` (the browser file layer: `store.ts` load/save/merge/restore over ports, `fs-access.ts` File System Access API, `persistence.ts` IndexedDB handles + backups, `workspace.ts` folder/file/upload/demo sources), `src/ui/state/session.svelte.ts` (the editing session), `src/ui` (Svelte 5 app), `src/i18n/ru.ts` (all UI strings), `tests/` (Vitest unit in `tests/{shared,lua,data,ui}`, `tests/e2e` Playwright with OPFS standing in for a user's folder, synthetic fixtures in `tests/fixtures/`). UI rules: dark only, strict CSP (no inline styles, no Svelte transitions), no external requests except the optional Twitch login to `id.twitch.tv`. `src/ui/fsa-check.*` is a throw-away manual-check page (dev server only), to be deleted after the owner's check. `spikes/ui-svelte` is a throw-away reference.
- Never log config contents. No analytics, no third-party scripts. The only network traffic is the optional Twitch login (device-code flow to `id.twitch.tv`, `src/ui/data/twitch-flow.ts`); the Twitch token goes straight into the plugin folder's `data/helix.json` (`helix-file.ts`) and is never kept in UI state, logged, backed up or shown. The config never leaves the browser.

## Hard facts
- The plugin reads `config.json` only at start or `/autoreply reload`, and rewrites the whole file on every change it makes. The UI writes and tells the user to run `/autoreply reload`. Never edit live state (`active_until`, timer `started_at`/`game_id`/`enabled`) from stale data.
- Empty lists may be stored as `{}` or `[]` depending on the Leafyrino build (`[]` accepted on load: VERIFIED on Nightly 2.5.5, macOS); read both, and the app writes `{}` until the owner decides otherwise. Preserve unknown keys. Ids are never reused.
- Rule evaluation in the UI = the plugin's real Lua run in WASM (vendored copies in `vendor/plugin/`, synced by script, hash-checked). Do not re-implement matching in TypeScript.
- The site is static: strict CSP and headers in `src/shared/security-headers.ts` (mirrored in `vercel.json`, tested), no external requests except `connect-src https://id.twitch.tv` for the optional Twitch login (tested in `tests/shared/csp.test.ts` and e2e), the config never leaves the browser.
- No downloads and no release build: customers open a URL. Direct file access needs a Chromium browser; other browsers use open/download.
