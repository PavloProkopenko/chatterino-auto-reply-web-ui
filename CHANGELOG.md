# Changelog

All notable changes to this project are documented here.

## [Unreleased]
- Twitch login on the site (plugin 0.8.0+): Settings "Twitch API" card with device-code login (code and link shown, copy, cancel), logout with revoke and the "Использовать Twitch API" switch (`helix_enabled`); the login is written to the plugin's `data/helix.json` and is never kept in the page. CSP now allows `connect-src https://id.twitch.tv` and nothing else. The Redeems "Add" button is disabled until logged in and the Twitch API is on. Sidebar: an "Обновить плагин" button appears when the bundled plugin is newer (one click, backup in `.backup/<version>/`). Fixed: "Плагин новее, чем это приложение" was always shown because the known version was never bumped; it now follows the bundled plugin version.
- Plugin 0.7.x: the save banner no longer asks for `/autoreply reload` when the plugin is 0.7.0 or newer (it applies the file itself in ~3 s); older or unknown versions keep the command, with a hint to update. After a plugin update or rollback the site writes `data/.plugin-update` and says the plugin must be switched off and on (Settings, Plugins) or Leafyrino restarted. Default `global_min_gap` is 1; bundled plugin 0.7.2.
- Phase 4: Timers and Redeems pages. Timers: list with state ("запущен с ... по файлу на момент открытия"), order by buttons and drag, start ("Запустить сейчас", with the zero-elapsed warning) and stop, delete with confirmation; constructor (channel, "и ещё" conditions, reply with `{time}` required, format with the plugin's real examples, category behaviour, skip options). New timers are saved off. Editing never touches live state (`enabled`, `started_at`, `game_id`); a start the plugin overruled is reported. Older or unknown plugin versions: view, start/stop and delete only. Redeems: list with enable switch, order, delete; constructor with duration read by the plugin's parser and shown in words, quick buttons, duplicate/contained-title warnings, long-mute confirmation, moderator-account and empty-protected-list notes. The Rules preview now runs running timers first; the Timers page adds a sample elapsed time. Shared constructor components (conditions, name, skip options, reply, channel) and shared list helpers (order, drag, focus); Lua checks for timers, redeems and the combined preview in `src/lua/uichecks.lua`; dev-only fixture cross-check now includes the plugin's timer scenario.
- Phase 3: Rules page and constructor. List with search, position numbers ("first matching rule wins"), enable/disable, up/down buttons and drag, bulk enable/disable, move to top/bottom and delete with confirmation, and per-rule hints (reply/condition/name problems, channel not in the list, possibly shadowed by an earlier rule, plugin version too old). Side-panel constructor (name with a suggestion, "и ещё" condition chain, flags, patterns only under "Для опытных", reply with `{user}` button and a byte counter, channels, skip options) and a live preview that runs the list through the plugin's own Lua. New Lua module `src/lua/uichecks.lua` (the plugin's `check_reply` as a marked copy, covered by a contract test) and a flag table in the shim. Dev-only cross-check against the plugin repo's labelled chat fixture (`PLUGIN_REPO`).
- Phase 2c: open + download is the main flow. Chrome refuses `~/Library/Application Support/chatterino/Plugins/` as a folder and `data/config.json` as a file ("contains system files"), so the welcome screen leads with a plain "open config.json" button that is never blocked; direct folder/file access is a secondary option with an explanation. In download mode, saving first asks the user to open the current `config.json` again, merges the edits onto it (live state comes from the fresh file), then downloads and shows a copy-able `cp`/`copy` command to put the file back. Direct folder/file access is gone from the production page (kept in dev and e2e builds so its code stays tested); `info.json` can be opened as an optional second file to learn the plugin version, otherwise the version stays unknown and version-gated settings stay off. Plugin-side request drafted in `docs/plugin-request-config-location.md` (not sent).
- Phase 2b: the browser file layer. The site reads and writes the plugin's config itself (File System Access API, handle remembered in IndexedDB, backups in browser storage, change polling), with open/download for other browsers and a demo mode. The local server, its proxy and `valibot` were removed.
- Direction change: hosted static site on Vercel. Removed the executable build, bundles, release pipeline, tab lifecycle, browser opener and `release-check`; added `pnpm dev` / `pnpm preview` / `pnpm build`, `vercel.json` and shared security headers. The local API server stays dormant until the browser file layer (Phase 2b) replaces it.
- Phase 0: repository environment, vendoring script, stack spikes, prepare scripts, CI skeleton.
- Phase 1: config model (normalise, minimal-diff render, JSON style detection), id counters, three-way merge with live-state protection, safe file store (backup, atomic write, retry), discovery, app settings, version gating, WASM Lua host with worker timeout, local HTTP API with Host/token/Origin checks, compiled-binary smoke test.
- Phase 2: Russian dark UI served by the executable (shell, sidebar, save bar, reload banner, config picker, history/restore, per-field conflict dialog, Settings page), session store with undo/redo, tab lifecycle (opens the browser, exits with the last tab), Playwright e2e and accessibility checks.
